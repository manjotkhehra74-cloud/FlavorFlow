On the server, after dry-run, verify:

```bash

sqlite3 /opt/flavorflow/server/data/erp.db "SELECT planned_date, product_id, produced_cb FROM batches WHERE status='COMPLETED' AND planned_date > '2026-10-05' AND planned_date <= '2026-10-07' ORDER BY planned_date;"

# Recorded consumption in window
sqlite3 /opt/flavorflow/server/data/erp.db "SELECT material_id, SUM(qty) FROM packing_txns WHERE txn_type='CONSUMED' AND txn_date > '2026-10-05' AND txn_date <= '2026-10-07' GROUP BY material_id;"

# Current stock for matched materials
sqlite3 /opt/flavorflow/server/data/erp.db "SELECT id, name, stock, unit FROM packing_materials WHERE name IN ('Shrink Soya 740g', 'Jerry Can 4Ltr', 'Soyabean') ORDER BY id;"
```

If recorded consumption already equals expected BOM consumption for a material, the script will use recorded (authoritative) and proposed final = physical - recorded. This prevents double-deduction.

If recorded is 0 but expected >0, it means production was completed but packing consumption was not yet recorded — script will use expected as deduction, so final = physical - expected. This accounts for production that happened after the physical count photo but before 07/10 closing.
